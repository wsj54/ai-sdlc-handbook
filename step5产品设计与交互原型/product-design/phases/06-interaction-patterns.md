# 阶段 06：交互规范

## 目标

抽取跨页面通用的交互模式、反馈规则、错误处理和状态约定，避免每个页面重复描述，保证原型阶段风格一致。

## 输入

- 阶段 05 的页面详细设计（已写完各页面的交互和状态）。

## 动作

1. 从已完成页面中识别重复出现的交互模式，例如：
   - 删除 / 危险操作的二次确认；
   - 表单提交与校验；
   - 列表的加载、刷新、分页；
   - 搜索与筛选；
   - 空态与错误态的引导。

2. 把重复模式抽取为通用规范，编号 `INT-xxx`，写清适用场景和统一规则。

3. 补充三类通用规则（写入 TEMPLATE 06 节）：

   - **反馈规则**：操作成功 / 失败 / 进行中分别如何反馈（如“成功用轻提示，失败用可关闭的提示条”）。
   - **错误处理**：表单校验错误、网络错误、权限不足的通用处理。
   - **状态约定**：空态、加载态、错误态的通用呈现方式。

4. 检查阶段 05 的页面描述是否与通用规范冲突；冲突时以通用规范为准回改页面，或标记为特例并说明。

## 设计原则

- 只抽取“确实跨多个页面重复出现”的模式，不为单个页面的行为建通用规范。
- 通用规范要能被原型阶段直接套用，不写“合理处理”“适当提示”这类空话。

## 何时提问

- 通用反馈方式（如成功用 toast 还是内联提示）需要用户定调时；
- 危险操作的确认方式（弹窗确认 / 二次输入 / 撤销）需要用户取舍时；
- 不同页面存在不一致的交互，需要用户决定统一还是保留差异时。

## 完成标准

- 跨页面通用交互模式已抽取，规则明确可套用。
- 反馈、错误处理、状态约定三类规则已明确。
- 页面描述与通用规范一致，特例已标注说明。

完成后直接进入阶段 07。
