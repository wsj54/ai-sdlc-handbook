# 阶段 03：用户流程

## 目标

确定关键任务的用户路径与异常分支，让页面之间的关系有依据。

## 输入

- 阶段 02 的导航结构与站点地图。
- `REQUIREMENTS.md` 的用户故事（UC）、业务规则（BR）、验收标准（AC）。

## 动作

1. 识别核心闭环：谁 → 在什么情况下 → 完成什么 → 得到什么。

2. 为每条核心流程编号 `FLOW-xxx`，写清：
   - 触发条件（何时开始）；
   - 主要步骤（1 → 2 → 3 → …，写用户和系统行为，不写界面元素）；
   - 结束条件（何时结束、可观察结果）；
   - 异常分支（写清“用户看到什么 / 能做什么”，不写“系统处理错误”）。

3. 把流程关键节点对应到页面（引用 `PG-xxx`，若页面尚未编号，先留待阶段 04 回填）。

4. 检查：
   - 有没有核心流程走不通（断头、死路）？
   - 异常分支是否覆盖了 `BR` 和 `AC` 里的边界情况？
   - 简单操作是否被过度拆成流程（可并入页面交互）？

## 设计原则

- 只画核心闭环和关键异常分支，不为每个小操作都画流程图。
- 流程写行为，不写视觉；元素细节留在阶段 05。
- 异常分支必须落到“用户能做什么”，不能是空洞的“系统处理”。

## 何时提问

- 一个任务存在多种完成路径，哪种是主路径需要用户确认时；
- 异常情况下用户能否恢复、如何恢复不明确时；
- 流程是否需要多步骤向导还是一页完成，存在取舍时。

## 完成标准

- 核心闭环流程已梳理，正常路径完整。
- 关键异常分支已覆盖，且写清用户可见行为。
- 流程关键节点能对应到页面。
- 用户已确认关键流程取舍。

完成后直接进入阶段 04。
