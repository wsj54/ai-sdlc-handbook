# 阶段 01：上下文与输入

## 目标

建立设计基线：明确为谁设计、首版范围、设计约束和设计深度，并创建 `PRODUCT_DESIGN.md` 骨架。

## 输入

- `REQUIREMENTS.md`：核心事实来源（目标、用户、场景、功能、规则、验收、范围）。
- `FEASIBILITY_REVIEW.md`：设计约束、风险、移交技术阶段的问题。
- `INITIAL_REQUIREMENTS.md`：背景、用户、场景。
- `DEVELOPMENT_APPROACH.md`：开发模型，决定设计深度。
- `PRODUCT_BACKLOG.md`（如存在）：首版范围与优先级。

## 动作

1. 读取全部可用输入，提取：
   - 产品目标、一句话定位、成功标准；
   - 目标用户与角色、使用场景、使用环境（设备 / 网络）；
   - 首版功能范围（MVP / 首版 / 后续 / 不做项）；
   - 核心业务闭环；
   - 非功能约束中影响设计的部分（易用性、兼容性、离线等）；
   - `FEASIBILITY_REVIEW.md` 中移交第五阶段的设计约束和风险。

2. 识别开发模型，确定设计深度：

   | 开发模型 | 本阶段重点 |
   | --- | --- |
   | 瀑布 | 在约定范围内尽量完整地设计全部页面 |
   | 敏捷 / 增量 | 核心闭环页面详细设计，远期页面从简 |
   | 原型 | 重点设计需要验证体验的假设页面 |

3. 建立 `PRODUCT_DESIGN.md` 骨架：填写文档信息、状态说明、编号约定、设计原则与约束（01 节）。

4. 从输入中提炼设计原则和约束，写进 01 节；缺失的设计约束问用户补齐（见下）。

## 何时提问

- 首版范围与 `REQUIREMENTS.md` 冲突或缺失时；
- 使用环境（设备、屏幕、离线、平台）不清楚，且影响页面组织时；
- 设计约束缺失且会影响核心页面时（如“必须在手机上单手操作”）。

## 完成标准

- 文档骨架已创建，文档信息完整。
- 设计原则与约束已写入 01 节，来源清楚。
- 首版范围、目标用户、核心闭环已确认或标注 `assumption`。
- 设计深度已按开发模型确定。

完成后直接进入阶段 02，不要求用户再次调用。
