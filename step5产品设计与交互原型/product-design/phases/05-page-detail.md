# 阶段 05：页面详细设计

## 目标

把「详细」页面的结构、交互、状态、跳转写到原型阶段可以直接照着实现的程度。这是本阶段最核心的一步，也是 `PRODUCT_DESIGN.md` 对原型阶段的直接输入。

## 输入

- 阶段 04 的页面清单（`PG-xxx`，标注了「详细 / 从简」）。
- 阶段 03 的用户流程（`FLOW-xxx`）。
- `REQUIREMENTS.md` 的功能需求（`FR`）、业务规则（`BR`）、验收标准（`AC`）。

## 四要素：元素 / 交互 / 状态 / 跳转

每个「详细」页面必须齐备四要素，缺一不可标 `confirmed`。四要素共同构成原型阶段可实现的完整规格。

### 1. 元素（EL）——页面上有什么

列出页面上所有可见、可操作的元素，编号 `EL-xxx`，标注类型和作用。

| 字段 | 说明 |
| --- | --- |
| 编号 | `EL-xxx` |
| 元素名称 | 用户视角的名称（如“新建任务按钮”） |
| 类型 | 输入框 / 按钮 / 列表 / 卡片 / 导航 / 标签页 / 弹窗 / 提示 / 开关 / 下拉等 |
| 作用 | 这个元素是干什么的 |
| 是否必需 | 是 / 否（原型阶段据此判断能否裁剪） |
| 关联需求 | `FR-xxx` |

规则：

- 元素名称用业务语言，不用技术组件名（写“任务列表”不写“FlatList”）。
- 一个元素只对应一个作用；复合控件拆成多个元素。
- 元素必须能追溯到需求，不凭空出现“顺便加”的元素。

### 2. 交互（INT）——用户做什么、系统怎么响应

对每个可操作元素，写清触发动作和系统响应，编号 `INT-xxx`。

| 字段 | 说明 |
| --- | --- |
| 编号 | `INT-xxx` |
| 元素 | 引用 `EL-xxx` |
| 触发动作 | 点击 / 输入 / 滑动 / 长按 / 悬停 / 拖拽等 |
| 系统响应 | 系统做什么、结果是什么（写行为，不写技术实现） |
| 关联需求 | `FR-xxx` / `BR-xxx` |

规则：

- 响应写可观察结果，如“校验通过后新增一条任务，列表顶部出现新条目”，不写“调用接口”。
- 一条交互对应一个动作 + 一个结果；一个元素有多个动作时拆成多条。
- 有业务规则约束的交互（如权限、重复操作限制）要写出规则来源。

### 3. 状态（ST）——空 / 加载 / 错误 / 禁用 / 完成时怎么呈现

对页面和关键元素，写出各状态下的呈现方式，编号 `ST-xxx`。

| 字段 | 说明 |
| --- | --- |
| 编号 | `ST-xxx` |
| 元素 / 页面 | `EL-xxx` 或“整个页面” |
| 状态名 | 空 / 加载中 / 错误 / 禁用 / 完成 / 部分加载等 |
| 触发条件 | 何时进入该状态 |
| 呈现方式 | 显示什么、用户能做什么 |

规则：

- 至少覆盖：空态、加载态、错误态；有禁用 / 完成的场景也要写。
- 呈现方式写“用户看到什么 + 能做什么”，如“空态显示引导文案和‘新建’按钮”，不写“显示空提示”。
- 错误态要写用户能否恢复、如何恢复。

### 4. 跳转（LINK）——点击后去哪

列出每个可点击动作的跳转目标或页面变化，编号 `LINK-xxx`。

| 字段 | 说明 |
| --- | --- |
| 编号 | `LINK-xxx` |
| 来源元素 | `EL-xxx` |
| 触发动作 | 点击等 |
| 目标页面 / 变化 | `PG-xxx` / 弹窗 / 原地刷新 / 返回上一页 |
| 说明 | 跳转条件或携带信息 |

规则：

- 每个可点击元素必须有明确的跳转目标或原地变化，不得出现“断头”链接。
- 返回、取消、关闭等也要写清去向。
- 弹窗、抽屉等临时层要写清从哪触发、如何关闭。

## 逐页设计动作

1. 按页面清单顺序，先做「详细」页面，后做「从简」页面。

2. 对每个「详细」页面：
   - 先写页面目标、访问路径、关联需求；
   - 再列元素（EL），据此推导交互（INT）、状态（ST）、跳转（LINK）；
   - 每写一项都回填关联需求编号。

3. 对每个「从简」页面：
   - 只写页面目标和元素（EL）清单；
   - 其余标「从简」，说明原型阶段可自行把握。

4. 每完成一个页面，立即更新 `PRODUCT_DESIGN.md` 05 节，不攒批。

## 提问优先级

按阻塞程度挑问，优先问会连锁影响多个页面的决策：

- 页面信息优先级（什么放前面、什么可折叠）不明确时；
- 一个操作有多种交互方式（弹窗 / 跳转 / 就地展开），取舍需用户决定时；
- 异常 / 空态处理方式需用户拍板时；
- 某些元素是否必需，涉及范围裁剪时。

## 完成标准

- 每个「详细」页面的四要素齐全，无缺失。
- 每个「详细」页面的元素、交互、状态、跳转都能追溯到需求或用户确认。
- 每个「从简」页面已写清目的和元素，并标注「从简」。
- 无断头跳转、无凭空元素。
- 四要素有缺失的页面未标 `confirmed`。

完成后直接进入阶段 06。
