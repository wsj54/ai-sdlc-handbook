# 产品设计阶段完成检查清单

> 宣告本阶段完成前，逐项核对。每条只能判「通过 / 不适用（附原因）/ 失败」；有失败项不得宣告完成。

## A. 输入与基线

- [ ] 已读取 REQUIREMENTS.md，并确认其为设计的事实来源
- [ ] 已读取 FEASIBILITY_REVIEW.md，提取设计约束、风险与移交技术阶段的问题
- [ ] 已读取 INITIAL_REQUIREMENTS.md 与 DEVELOPMENT_APPROACH.md（缺失时已在文档信息中标注）
- [ ] 文档信息填写完整（版本、日期、输入来源、开发模型、阶段状态）

## B. 设计原则与约束

- [ ] 设计原则已写明，且每条能指导具体设计判断
- [ ] 设计约束已提取（平台、设备、场景、合规、范围），并标注来源
- [ ] 视觉方向只写方向性约定，未出现具体色值、字号、间距
- [ ] 约束与原则无冲突；有冲突时已由用户确认处理方式

## C. 信息架构

- [ ] 导航结构清晰，页面层级无遗漏
- [ ] 站点地图已列出全部导航节点，父子关系正确
- [ ] 每个页面都能定位到唯一导航位置

## D. 用户流程

- [ ] 核心闭环流程已梳理（谁 → 什么情况 → 完成什么 → 得到什么）
- [ ] 关键异常分支已覆盖，且写清用户能看到什么、能做什么
- [ ] 流程关键节点能对应到具体页面（PG-xxx）

## E. 页面清单

- [ ] 首版范围内的所有页面均已列入清单
- [ ] 每个页面标注了访问角色和详细程度（详细 / 从简）
- [ ] 核心闭环涉及的页面均标为「详细」
- [ ] 明确不做的页面未混入清单，或已标注「后续版本」

## F. 页面详细设计（四要素）

- [ ] 每个「详细」页面的元素（EL）清单完整
- [ ] 每个「详细」页面的交互（INT）覆盖了各元素的可操作行为
- [ ] 每个「详细」页面的状态（ST）覆盖空 / 加载 / 错误 / 禁用 / 完成等必要情况
- [ ] 每个「详细」页面的跳转（LINK）目标明确，无断头链接
- [ ] 四要素缺任一项的页面未标 `confirmed`
- [ ] 「从简」页面已说明其目的和元素，未强行写满四要素

## G. 交互规范

- [ ] 跨页面通用交互模式已抽取（删除确认、表单校验等）
- [ ] 反馈规则已明确（成功 / 失败 / 进行中）
- [ ] 错误处理与空态、加载态约定已明确

## H. 追溯与一致性

- [ ] 每个页面、交互、状态都能追溯到 FR-xxx / BR-xxx 或用户确认
- [ ] 无凭空发明的页面、功能和字段
- [ ] 术语表已建立，全文使用统一术语
- [ ] 文档中无 `Q1=A`、`Q2=B` 等无法自解释的引用
- [ ] 编号只做索引，引用处写明了结论本身

## I. 状态与未决事项

- [ ] 已确认、待确认、暂定假设、暂缓、冲突五类信息区分清楚
- [ ] AI 的建议和推测均标为 `assumption` 或 `pending`，未写成 `confirmed`
- [ ] 待确认问题、暂定假设、暂缓事项均已记录并写明处理方式
- [ ] 设计决策记录完整（问题、选项、选择、结论、影响章节）

## J. 移交与完成

- [ ] 移交原型阶段的说明完整（首版范围、约束、视觉方向、核心页面、交互要点、待确认事项）
- [ ] 已完成独立审查，阻塞性问题已解决或记录
- [ ] 本阶段未越界：未产出 HTML / 视觉原型、未选技术栈、未写代码
- [ ] 用户已审查并明确确认设计文档
