# 阶段 06：结论分析、架构约束与交接

本阶段目标：对每项技术问题给出明确结论，形成技术决策建议和架构约束，完成向第七阶段的交接。模式 B 时本阶段与 phases/05 合并执行：验证完成即逐项下结论。

## 1. 逐项下结论

对每条 TV 项，对照成功标准和证据给出四档结论之一（见 [SKILL.md「四种结论状态」](../SKILL.md)）：

| 结论 | 证据要求 |
| --- | --- |
| 通过 | 必须有 `A 实测` 或 `B 文档` 级证据；只有 `C 推测` 的不得标"通过" |
| 有条件通过 | 有 A/B 级证据，但结论附带前提条件（如"需控制并发 ≤ N""需付费 API"） |
| 不通过 | 有 A/B 级证据证明无法满足要求或风险不可接受 |
| 尚未验证 | 缺少环境、数据或结果；保留风险，不得标记为已验证 |

每条结论写明：结论、依据（引用 EV/RES）、证据等级、限制与使用条件。

## 2. 对"不通过"和"有条件通过"做深入分析

不能只记录"效果不好"。逐项分析：

- 是否可以通过结构化输出、参数调整、工作流约束改善？
- 是否应该让用户确认后再执行（降低自主性要求）？
- 是否需要更换方案或服务商？
- 是否要调整 MVP 的功能范围或产品交互来绕开该问题？

分析结论与用户确认后，决定处理方式：

- 更换技术方案，再进行必要的验证（回到 phases/03/04，只针对替换项）。
- 降低功能复杂度，调整 MVP 范围（需求变更走反馈循环：AI 只提建议，**是否调整由用户决定**，用户确认后返回第三阶段更新需求文档）。
- 修改产品交互，绕开高风险技术（反馈给产品设计文档，标记待修订）。
- 保留待解决问题，推迟相关功能。
- 只有核心产品目标无法实现时，才讨论终止项目。

**本阶段的合格结果不一定是全部通过，而是明确知道哪些可行、哪些有条件、哪些不可行，以及接下来怎么做。**

## 3. 回答七个关键问题

汇总为第 7、8 章前，回答：

1. 当前推荐采用什么技术方案？
2. 为什么选择这个方案？
3. 是否存在更简单或风险更低的替代方案？
4. 方案有哪些局限和使用条件？
5. 是否需要调整现有需求或产品交互？
6. 是否会影响第七阶段的系统架构设计？
7. 是否还存在需要后续处理的高风险问题？

## 4. 形成综合技术结论（第 7 章）

- 7.1 已验证可行的方案（附证据等级）。
- 7.2 有条件通过的方案（附条件）。
- 7.3 不可行或不推荐的方案（附原因和替代方向）。
- 7.4 尚未验证的问题（附缺口：缺什么、建议何时补验）。

## 5. 产出架构约束（第 8 章）——交接核心

本阶段交接给第七阶段的主要依据：

- **8.1 推荐技术方向**：经验证支持的技术选择建议及理由。
- **8.2 必须遵守的技术约束**（`DC-xxx`）：技术版本、依赖条件、运行环境、性能边界、成本上限、外部服务的配额与限制等。第七阶段架构设计不得违反。
- **8.3 需要考虑的替代方案**：一旦主方案在架构阶段遇到问题，可退去的备选。
- **8.4 对后续架构设计的影响**：验证结果如何改变了架构设计的前提（如"必须引入重试机制""模型调用需设计降级路径""某功能需改为用户确认后执行"）。

## 6. 需求与产品设计调整建议（第 9 章）与遗留事项（第 10 章）

- 验证结果若要求调整需求或产品交互：列出建议，标注哪些文档待修订（AI 不直接改前序阶段文档，需求变更由用户确认后返回第三阶段处理）。
- 遗留风险与待办：尚未验证的问题、推迟的功能、需要上线前再测的项（如真实环境性能），写明影响和处理方式。

## 7. 交接检查清单

进入第七阶段前逐项核对（来自阶段交接的通过条件）：

| 检查项 | 通过条件 |
| --- | --- |
| 技术问题识别 | 已识别可能影响架构的关键技术问题 |
| 关键风险验证 | 高影响问题已验证，或有明确替代方案和风险处理方式 |
| 验证证据 | 所有标记"通过"的结论都有相应依据（A/B 级证据） |
| 技术选型依据 | 关键技术建议有调研或实验依据 |
| 架构约束 | 已明确技术版本、依赖条件、运行环境等重要限制 |
| 遗留问题 | 尚未解决的问题已记录，明确影响和处理方式 |
| 文档一致性 | 验证结果改变需求或产品设计时，相关文档已更新或标记待修订 |

任何一项不通过，回到对应阶段补齐，不宣告完成。

## 8. 用户验收

向用户展示：TV 清单结论汇总、七问答案、架构约束要点、需求调整建议、遗留风险。用户确认后：

- 更新 [CHECKLIST.md](../CHECKLIST.md) 各项状态。
- 询问用户是否进入第七阶段（系统架构设计，产物 ARCHITECTURE.md）。第七阶段技能尚未就绪时，到本阶段完成即停止，不调用不存在的技能。

## 完成标准

- 每条 TV 项均有四档结论之一，且证据等级合规。
- "不通过 / 有条件通过"的项有处理方式，处理方式已用户确认。
- 七个关键问题均有答案。
- 第 8 章架构约束完整（DC 条目可被第七阶段直接执行）。
- 交接检查清单全部通过。
- 用户明确确认"可以进入第七阶段"（或有条件进入及其条件）。
