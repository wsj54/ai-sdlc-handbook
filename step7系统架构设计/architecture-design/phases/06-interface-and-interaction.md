# 阶段 06：接口设计与模块交互

本阶段目标：设计前端与后端、后端内部模块、后端与模型服务、AI 与业务工具之间的交互方式。核心接口契约要明确到能指导编码，但不写实现代码。

## 1. 交互链路梳理

先画出系统的主要交互链路（文字或时序图），确认没有断链：

```text
用户 → 前端页面 → 后端接口 → 业务模块 → 数据库
用户 → 前端 AI 对话页 → 后端 AI 接口 → AI 服务模块 → 模型 API
                                    └─ 工具调用 → 业务模块 → 数据库
```

检查点：每条用户操作路径（来自 PRODUCT_DESIGN.md 的 FLOW-xxx）是否都有完整链路；链路上每个环节是否都有模块负责（对应 MOD-xxx）。

## 2. 前后端接口契约

核心接口（API-xxx）按以下要素写契约，**到契约粒度为止，不写实现**：

- 接口名称和用途。
- 请求参数（名称、类型、含义）。
- 返回数据结构（主要字段）。
- 错误码或异常返回方式。
- 是否需要流式响应（AI 对话通常需要）。

次要接口允许只列名称和用途。判断标准：后续编码 AI 拿到契约后不需要再问"这个接口应该传什么、返回什么"。

## 3. 内部模块与外部调用

- **后端内部模块调用**：直接函数调用还是事件机制；同步还是异步。个人项目默认直接调用，不为简单场景引入消息队列。
- **模型服务调用**：通过统一模型调用层（第 4 章选型）还是直接 SDK；超时、重试、流式的约定。
- **AI 工具调用链路**：AI 服务模块如何调用业务模块（工具注册方式、权限控制），详细设计留到 phases 07，这里只定链路。
- **外部 API 集成**：第三方服务的调用位置（收拢在哪个模块）、密钥管理方式。

## 4. 异常与数据校验

- 异常返回的统一格式（错误码、用户可读信息、日志记录分工）。
- 数据校验责任：前端校验（体验）与后端校验（安全底线）各自负责什么。

## 5. 异步与实时通信

只在确有需求时设计：AI 长任务是否需要后台执行与进度查询、是否需要 WebSocket / SSE。没有明确需求的个人项目不引入实时通信组件。

## 6. 讨论并确认

- 接口风格取舍（如 REST vs 简单 RPC 风格）、流式方案等存在取舍的决策向用户说明后确认，登记 DEC-xxx。
- 纯技术性约定（统一错误格式字段名等）AI 可直接确定，落盘时说明。

## 7. 落盘

- 第 7 章"接口与交互设计"：前后端接口契约（API 清单 + 核心契约详情）、内部模块接口约定、外部服务接口、接口数据结构、异常处理规范。
- 核心业务流程图 / 时序图按级别要求绘制（见 SKILL.md 架构图选取表）。
- 精简级别：本章可与第 6 章合并执行，只保留核心接口契约。

## 完成标准

- 每条用户操作路径都有完整交互链路，无断链、无无主功能。
- 核心接口契约要素齐全（名称、用途、参数、返回、错误处理），足以指导编码。
- 内部调用、模型调用、外部集成的交互方式已约定。
- 异常返回格式和数据校验责任已明确。
- 异步 / 实时通信按需设计，无为了完备而引入的组件。
- 第 7 章与第 5、6 章的模块和数据设计一致。
