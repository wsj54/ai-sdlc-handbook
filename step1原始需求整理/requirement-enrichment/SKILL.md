# 需求丰富

把“只有一个模糊想法”聊成“可以开始正式整理的需求素材”。

这是需求整理之前的**发散阶段**：帮用户把没说出口、没想到、说不清的部分说出来。它不是需求分析，也不是正式需求文档；它不判定五种正式状态，不裁决冲突，不定义功能规则、MVP、优先级和技术方案。

产出：`RAW_REQUIREMENTS_BRIEF.md`，模板见 [TEMPLATE.md](./TEMPLATE.md)。之后交给 `initial-requirements` 收敛成正式文档。

## 与 initial-requirements 的分工

| | 本技能 | initial-requirements |
| --- | --- | --- |
| 阶段 | 发散、补全、激发 | 收敛、结构化、澄清、冲突检测 |
| 问题 | “你还没考虑 X，要不要聊聊？” | “你说的 X 具体指哪一种？” |
| 对 AI 建议 | 可以提，必须标注并等待用户取舍 | 不新增用户没说的内容 |
| 状态 | 用户确认 / AI 建议 / 待探索 | 五种正式状态 |
| 产物 | `RAW_REQUIREMENTS_BRIEF.md` | `INITIAL_REQUIREMENTS.md` |
| 结束 | 素材足够开始整理 | 用户验收，进入下一阶段 |

本技能不接管 `initial-requirements` 的职责。发现需求之间可能矛盾时，只把它作为“值得确认的张力”提出来，不在本阶段裁决。

## 输入

接收用户的一句话、零散描述、笔记、聊天记录或已有文档。用户只给一句“我想做一个 X”也可以开始。

用户什么都没说时，只问一个开放问题：

```text
用一句话说说你想做什么，或者你想解决什么问题？
```

如果项目里已有文档，先读。能从文件里查到的事实自己查，只有用户知道的目标、偏好和取舍才问用户。

## 工作流程

### 1. 接住输入并复述

先用 5–7 条 bullet 复述你理解到的内容：

- 想解决的问题
- 目标用户
- 典型场景
- 已经想到的功能或方向
- 已知限制
- 用户明确不要的东西
- 还没想清楚的地方

然后问：`我理解得对吗？哪里需要改？`

完成标准：用户确认或纠正了复述；`RAW_REQUIREMENTS_BRIEF.md` 的 v0 已落盘。

### 2. 维度扫描

按「需求雷达维度」逐项判断：已有、模糊、空白。

用一张紧凑的表展示给用户，只列与当前项目相关的维度，不要一次倾倒所有问题。然后选出 2–4 个最值得先聊的空白或模糊项。

完成标准：雷达 v0 已写入交接稿；本轮要聊的空白已选定。

### 3. 每轮探索提问

每轮 2–4 个问题，优先问“不聊清楚就没法继续”的空白。每个问题用下面的格式：

```text
问题 1｜<能独立理解的标题>
为什么问：<它会影响哪个判断>
可选方向：
A. <方向 A 的具体含义>
B. <方向 B 的具体含义>
C. <方向 C 的具体含义>
推荐：<推荐项 + 理由>
灵感提示（可选）：<一个类比、极端场景或反问>
```

规则：

- 选项要具体，写出含义，不要只给抽象词或字母。
- 至少有一个选项可以是 AI 主动想到的方向，但必须标明“这是 AI 的建议”。
- 用户卡住时，给 2–3 个例子或极端场景，而不是替用户选。
- 问完一轮就停，等待回答。
- 收到回答后，先写成一条决策记录（完整问题、用户选择的含义、结论），再更新交接稿。

完成标准：本轮问题得到回答，或用户明确说“够了”“暂不决定”；回答已转成自包含的决策记录。

示例：用户说“我想做一个记账工具”。不要直接生成功能清单。先复述，再用雷达标出空白；第一轮可以问“谁用、什么时候记、现在怎么记”，每个问题给 2–3 个具体方向；如果 AI 提议“自动识别短信账单”，标为 `SUG-001`，等用户取舍。

### 4. 记录与分离

每轮回答后立即更新交接稿，把内容分成三类：

| 类别 | 记录方式 |
| --- | --- |
| 用户已确认 | 用户原话或明确回答，写成“用户确认：<结论实质>” |
| AI 建议 | `SUG-001`，写明建议、理由、用户取舍（采纳 / 不采纳 / 待定） |
| 仍未知 | 还没回答的问题，标为“待探索” |

同时在第 04 节写一条决策记录：完整问题、用户选择的含义、结论、影响。

规则：

- AI 建议不能直接写成用户需求；只有用户明确说“采纳”才转为“用户采纳”。
- 用户说“不知道”“还没想好”时，记入“待探索”，不要用推测填空。
- 用户只回“选 B”时，把 B 的内容写进结论，不只记字母。
- 用户说“按推荐”时，把推荐内容本身写进结论。
- 用户的新回答与之前矛盾时，指出前后差异，请其确认以哪条为准。
- 用户拒绝过的方向要留在稿里，避免下一轮重复提议。

完成标准：交接稿反映了本轮回答；建议与用户原话分开；新增决策记录自包含；新出现的空白已登记。

### 5. 循环与停止

更新雷达，看看是否还有“不聊清楚就无法开始整理”的空白。有，且用户愿意继续，就回到第 3 步；没有，就收口。

满足以下任一组合即可停止：

- 用户能说清问题、目标用户、1–2 个典型场景、已有功能或方向、已知限制。
- 交接稿里的“仍未知”不会阻塞 `initial-requirements` 开始整理。
- 用户明确说“够了”。

不要追求把每个维度都问满。本阶段的目标是“够用”，不是“完整”。

完成标准：停止条件满足，且用户知道可以进入下一步。

### 6. 收口与交接

向用户提交四样东西：

- 已经明确的内容。
- AI 提过、用户采纳/拒绝/待定的建议。
- 仍然未知、需要下一阶段继续确认的事项。
- 一个明确问题：`现在进入 initial-requirements 整理吗？`

用户确认后：

- 保存最终版 `RAW_REQUIREMENTS_BRIEF.md`。
- 提示用户把交接稿一起交给 `initial-requirements`。
- 不自动替用户开启下一阶段；用户明确同意后再切换。

完成标准：交接稿已保存；用户知道下一步怎么做。

## 需求雷达维度

| 维度 | 引导问题 |
| --- | --- |
| 问题与目标 | 为什么做？不做会怎样？成功是什么样？ |
| 用户与角色 | 谁使用、谁受益、谁维护？有没有不同角色？ |
| 场景与流程 | 什么时候用？什么触发？步骤是什么？什么时候结束？ |
| 功能与替代 | 现在怎么解决？最少需要哪个动作？有没有替代方案？ |
| 数据与内容 | 数据从哪来？要存什么？谁拥有？是否敏感？ |
| 权限与安全 | 谁能看、改、删、分享？是否需要登录？ |
| 通知与提醒 | 什么时候提醒？通过什么渠道？频率如何？ |
| 约束与非功能 | 设备、离线、网络、性能、预算、时间、合规？ |
| 成功信号 | 怎么知道它有用？什么情况算失败？ |
| 范围与边界 | 明确不做什么？哪些以后再做？ |
| 风险与例外 | 空数据、异常、多人冲突、误操作时怎么办？ |

按项目需要取用，不必逐项建表。

## AI 建议规则

- 每条建议都有编号 `SUG-001`，并注明“AI 建议，不是用户需求”。
- 建议要带理由和适用条件，不能只给结论。
- 用户采纳后，写成“用户采纳 SUG-001：……”，来源仍保留。
- 用户拒绝后，记录“已拒绝”，后续不再重复提议。
- 用户待定时，保留在稿里，进入下一阶段再处理。
- 建议是选项，不是功能清单；不要用一串功能名淹没用户。

## 记录规则（自包含）

交接稿会被下一个对话直接读取，每条记录脱离原对话仍然成立。

- 代号只做索引，不做含义载体。`S-001`、`SUG-001`、`UC-001` 可以出现，但引用处要写出内容本身。
- 不写 `Q1=A`、`Q2=B` 这类引用；问题和选项含义都要落盘。
- 不把“按推荐”“照你说的”“其余都同意”当成结论；写出被采纳的内容。
- 第 04 节每条决策记录包含：完整问题、用户选择的含义、结论、影响。
- 第 01.1 节的原始片段原样保留；其中无上下文的字母回答，在第 04 节还原。
- 无法还原的字母回答标“待探索”，请用户补充，不用猜测补齐。
- 交付前全文搜索 `Q\d`：只允许出现在第 01.1 节原话和第 04 节还原行中。

## 边界

| 本阶段做 | 本阶段不做 |
| --- | --- |
| 帮用户想全、说具体 | 写正式需求文档 |
| 扫描维度、提出可选方向 | 判定五种正式状态 |
| 记录用户确认与 AI 建议 | 裁决需求冲突 |
| 标记仍未知 | 定义功能规则、MVP、优先级、验收标准 |
| 产出交接稿 | 技术选型、架构设计、实现方案 |

用户在本阶段追问下一阶段内容时，记录为“待下一阶段”，并说明现在不展开。

## 交付物

- `RAW_REQUIREMENTS_BRIEF.md`：按 [TEMPLATE.md](./TEMPLATE.md) 生成。
- 默认路径：`docs/01-原始需求/RAW_REQUIREMENTS_BRIEF.md`；用户指定路径时以用户为准。

## 退出条件

- 用户能说清问题、目标用户、1–2 个典型场景、已有功能或方向、已知限制。
- 交接稿包含用户原话、已确认内容、关键问答结论、AI 建议及取舍、仍未知事项和约束。
- 交接稿不出现无法自解释的 `Q1`、`Q2` 引用；代号只做索引。
- 用户知道下一步是 `initial-requirements`，并同意交接。
